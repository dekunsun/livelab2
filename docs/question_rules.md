## 2. 主集

一个“段”= 一个异常运行里的一个可见异常，由首个连续标签 2 段定义。进入主集的条件：

1. 首个连续标签 2 段长度 ≥ 600 秒；
2. 起点前的档案 ≥ 300 秒。档案起点 = Operation 开始；对一个运行里的后续段，档案起点 = 上一段异常结束（标签回到 0）的时刻，之前的数据不进档案；
3. 该段对应的 YAML 记录写了观测传感器（`madeBySensor.Sensor.id`），且该传感器在传感器文件里。

按此规则，公开部分 25 段（1.0 没用过 10、1.0 用过 15；首段 18、后续段 7）。保留集的段数在生成时由同一规则算出，只记数目。
三部分（公开未用、公开且 1.0 用过、保留集）分开报，不合并。

次要题集：可见段 < 600 秒的段只问 t₁；注入误报题（第 6 节）。

## 3. 两个提问时刻

- t_on = 首个连续标签 2 段的起点（相对秒）。
- t₁ = t_on + δ，δ ~ U[60, 300] 秒，每题独立，种子 = sha256("livelab2-t1|" + 题目编号) 的前 16 位十六进制。
- t₂ = t_on + floor(0.8 × L)，L = 该段标签 2 段的长度（秒）。
- t₁、t₂ 各自独立会话；t₂ 的会话看不到 t₁ 的任何内容。
- 系统在 t 时的标记文字：“通道 X 现在偏离正常范围”。X 是固定通道（第 4 节）。不说何时开始。

## 4. 固定通道与预算

- 固定通道 = 该段 YAML 记录里专家指名的观测传感器；多个就全要，c = 个数。t₁、t₂ 和所有组用同一组。
- 预算 K ∈ {600, 1,800, 3,600}，单位是每个通道的原始读数个数（1 秒 1 个），按唯一的（通道，秒）计。
- 当前视图（各组相同，不计入 K）：仪器清单（来自 tags.csv，只给类型和位置，不给标签名）；t 时刻 18 个传感器的读数；固定通道最近 1,800 秒的 300 秒均值（6 个数）；“数据完整到 t”。
- 哪些组跑哪些 K：t₁ 只跑 1,800；t₂ 跑 600 / 1,800 / 3,600；B 只跑 1,800；保留集只跑 1,800。

## 5. 对照组

| 组 | 输入 | 工具 |
| --- | --- | --- |
| A | 当前视图 | 无 |
| E | 当前视图 + 固定通道 [t − K, t] 的原始数据 | 无 |
| D | 当前视图 | `get_window(start, end)`：固定通道、整数秒、原始 1 秒数据；每题最多 4 次；累计唯一秒数 ≤ K；超出剩余预算的请求整条拒绝并告知剩余预算；超过 t 的部分截掉并记录；返回实际提供的 (start, end, n) |
| B | 当前视图 + 固定通道一段长 K 秒、含 t_on、结束 ≤ t 的原始数据；t_on 在窗内的位置 u ~ U[0.2, 0.8]，种子 = sha256("livelab2-oracle|" + 题目编号) | 无 |
| F | 固定通道 [0, t] 的全部原始数据 | 不用大模型：PELT（`ruptures`），去趋势后的残差，惩罚参数只在正常运行上定（正常运行每小时 ≤ 1 个变点），报 t 之前最后一个变点 |
| G | 无 | 一律报 t |

所有需要模型的组用同一份任务说明；任务说明写明：起点的定义（证据第一次可见，不是原因）、容差、缺口按区间、预算 K 与剩余量、“早于 T”选项。

## 6. 答案与计分

`report` 字段：`onset`（一个相对秒；或区间 [a, b]；或 `earlier_than: T`）、`evidence`（引用的时间段）、`cause`（故障库类别或 `unknown`）、`state`。

- 起始定位：|onset − t_on| ≤ 容差 算对。容差三档 60 / 120 / 180 秒，主结果用 120，三档都报。
- 区间答案：t_on ∈ [a, b] 且 b − a ≤ 2 × 容差 算对；更宽的区间记为“过宽”。
- `earlier_than: T`：若 T ≤ 模型实际拿到的最早数据时间 + 容差，记为“承认窗口外”（不算对错，单独计）；否则记为错。
- 早于 t_on 且落在标签 1 区间内：记“早于证据”，单独计，人工复核引用的读数后分“真先兆 / 猜的”。
- 缺口：起点落在记录缺口里时真值为区间 (最后一个正常读数, 第一个异常读数]；本数据集有时间戳的行之间无缺口，此规则只在 2.1 人为制造缺口时生效。
- 注入误报题：正常运行，t 按种子随机抽（≥ 1,800 秒处），系统标记一个随机传感器；正确答案 `onset: none`。
- 覆盖率：每个计数旁写“有答案 / 登记题数”。超时、传输失败、撞输出上限的题不计入任何一项，单独报。
- 成本：每题实际用掉的唯一秒数和实际计费 token。

花费上限 = 冒烟实测单题成本 × 题数 × 2。估算方法和数字在设计文档“花费”一节。

## 9. 自动检查（每次运行）

1. 发给模型的每个数值的时间 ≤ t；
2. 请求里没有文件名、运行编号、钟面时间、揭示性词语；
3. 同一题同一 t 重放两次，工具返回完全一致；
4. 每次工具调用返回的最晚时间戳 ≤ t；
5. 每题每通道唯一秒数 ≤ K；E、B 的窗口长度恰为 K；
6. 每个运行时间单调、无跨午夜；模型收到的全是相对秒；
7. 输出上限 ≥ 8k，记停止原因。
