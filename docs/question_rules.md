## 0. 定规则之前已经看过的汇总信息

规则是在看过下列汇总数字之后定的，如实记录（都在 `docs/timeline.md`，没有任何单条异常的取值）：

- 非保留集 102 个运行的采样间隔、时长、通道数、YAML 记录数；
- 异常片段的阶段模式计数；首个连续标签 2 段 ≥ 10 分钟的段数（30）及其长度四分位（11.7 / 22.7 / 44.8 分钟）；
- 起点前档案长度的分位数；每个运行的可见段数；相邻段间隔；按第 2 节规则计出的主集段数。

没有算过任何一道题“E 的窗口是否覆盖 t_on”。

## 1. 数据

- Zenodo 17395543，本地副本 1.1.3 版（2026-09-02 发布），CC BY 4.0。标签包 sha256 `2fc22d8d…bdd1cb`（全文在 `docs/data/holdout_draw.txt`）。
- 只用 Operation 阶段的传感器文件和标签文件。Startup / Shutdown 不进档案。
- 时间：数据集只有 时:分:秒。入库时转成 Operation 开始后的整数秒；每个运行断言时间单调、无跨午夜；无时间戳的行丢弃并计数。
- 标签含义（Arweiler et al., Sci Data 2026 原文）：1 = “induced, but its effects are not yet observable”；2 = “becomes observable in any of the sensor readings”；3 = 恢复期；0 论文未定义，按“无异常”用。可观测时刻由作者事后按经验评定，边界“approximate”。
- 传感器图例：复用 1.0 修正过的 `data/realdata/tags.csv`，不改。

## 2. 主集

一个“段”= 一个异常运行里的一个可见异常，由首个连续标签 2 段定义。进入主集的条件：

1. 首个连续标签 2 段长度 ≥ 600 秒；
2. 起点前的档案 ≥ 300 秒。档案起点 = Operation 开始；对一个运行里的后续段，档案起点 = 上一段异常结束（标签回到 0）的时刻，之前的数据不进档案；
3. 该段对应的 YAML 记录写了观测传感器（`madeBySensor.Sensor.id`），且该传感器在传感器文件里。

按此规则，公开部分 25 段（1.0 没用过 10、1.0 用过 15；首段 18、后续段 7）。保留集的段数在生成时由同一规则算出，只记数目。

**样本量的读法**：公开 25 段，不是“38 对”；25 对里 3 题就是 12%，所以每组一次运行是筛查，结论用计数、不用比例，差 3 题以内不解读。三部分（公开未用、公开且 1.0 用过、保留集）分开报，不合并。

**后续段的切分是真值辅助的**：知道上一段何时结束用的是专家标签，真实监控里系统未必知道（产品里对应操作员确认恢复的记录）。主分析用全部 25 段；同时登记一个敏感性分析只用 18 个首段；两者符号不一致就都报、不下结论。

次要题集：可见段 < 600 秒的段只问 t₁；注入误报题（第 6 节）。

## 3. 两个提问时刻

- t_on = 首个连续标签 2 段的起点（相对秒）。
- t₁ = t_on + δ，δ ~ U[60, 300] 秒，每题独立，种子 = sha256("livelab2-t1|" + 题目编号) 的前 16 位十六进制。
- t₂ = t_on + floor(0.8 × L)，L = 该段标签 2 段的长度（秒）。
- t₁、t₂ 各自独立会话；t₂ 的会话看不到 t₁ 的任何内容。
- 系统在 t 时的标记文字：“通道 X 现在偏离正常范围”。X 是固定通道（第 4 节）。不说何时开始。

## 4. 当前视图、固定通道与预算

**当前视图**（所有组相同，不计入预算）：

- 仪器清单（来自 tags.csv，只给类型、位置和单位，不给标签名）；
- t 时刻 18 个传感器的读数；“数据完整到 t”；
- **粗图**：固定通道从档案起点到 t 的 600 秒均值序列（一次运行最多约 70 个数）。分辨率 600 秒 ≥ 3.3 × 最宽容差（180 秒），粗图本身给不出容差内的答案，但能告诉模型该往哪段看，对应产品里的趋势屏；
- 系统标记（第 3 节）。

**固定通道** = 该段 YAML 记录里专家指名的观测传感器；多个就全要，c = 个数。t₁、t₂ 和所有组用同一组。

**预算 K**：每个通道最多暴露给模型的原始读数个数（1 秒 1 个），按唯一的（通道，秒）计。**K 是上限，不是必须用完的量**：档案比 K 短时，E 和 B 拿到整段档案，此时 E = B，这类题测的是“读”不是“找”，按“档案是否长于 K”分层报告，不剔除。

K ∈ {600, 1,800, 3,600}。t₁ 只跑 1,800；t₂ 跑 600 / 1,800 / 3,600；B 只跑 1,800；保留集只跑 1,800。

## 5. 对照组

| 组 | 输入 | 工具 / 算法 |
| --- | --- | --- |
| A | 当前视图（含粗图） | 无 |
| E | 当前视图 + 固定通道 [t − min(K, 档案长度), t] 的原始数据 | 无 |
| D | 当前视图 | `get_window(start, end)`：固定通道、整数秒、原始 1 秒数据；每题最多 4 次；累计唯一秒数 ≤ K；超出剩余预算的请求整条拒绝并告知剩余预算；超过 t 的部分截掉并记录；返回实际提供的 (start, end, n) |
| B | 当前视图 + 固定通道一段长 min(K, 档案长度)、含 t_on、结束 ≤ t 的原始数据；t_on 在窗内的位置 u ~ U[0.2, 0.8]，种子 = sha256("livelab2-oracle|" + 题目编号)；窗口越界时整体平移到档案内 | 无 |
| F | 固定通道 [0, t] 的全部原始数据 | 不用大模型。F1：PELT（`ruptures`）在去趋势残差上的最后一个变点。F2：“最后一次持续正常”——t 之前残差最后一次连续 m 秒落在参考带内的时刻之后一秒。去趋势方法、参考带宽、m、PELT 惩罚只用正常运行定（正常运行每小时 ≤ 1 次误报），不在异常题上调。F1 已知偏弱（异常开始后继续恶化会产生多个变点），F2 是主要的经典对照，F1 只作参照 |
| G | 无 | 一律报 onset = t |

所有需要模型的组用同一份任务说明；任务说明写明：起点的定义（证据第一次可见，不是原因）、容差、答案的三种写法、证据不够时该怎么答、预算 K 与剩余量。

## 6. 答案与计分

`report` 字段：`onset`（一个相对秒；或区间 [a, b]；或 `earlier_than: T`；或 `none`）、`evidence`（引用的时间段）、`cause`（故障库类别或 `unknown`）、`state`。

**指标一 精确定位**（分母 = 全部登记题）：点答案 |onset − t_on| ≤ 容差，或区间答案含 t_on 且 b − a ≤ 2 × 容差，算命中。容差三档 60 / 120 / 180 秒，主结果用 120，三档都报。区间过宽、`earlier_than`、“无法确定”都不算命中，也不自动算编造。

**指标二 证据校准**（分母 = 全部登记题；由审计日志机械判定，不看模型自述）：

1. 先算每题的**证据覆盖**：模型实际收到的原始数据是否覆盖 [t_on − 容差, t_on + 容差]。
2. 原始已覆盖：点答案或 ≤ 2 × 容差的区间 = “有依据”；更宽的区间、`earlier_than`、“无法确定” = “有证据却弃权”。
3. 原始未覆盖：答案须是区间或 `earlier_than`，两端落在模型实际收到数据的时刻（原始窗口边缘或粗图的 600 秒格边），含 t_on，宽度不小于 min(600 秒, 原始覆盖缺口) = “校准”；点答案或更窄的区间 = “编造精度”；区间不含 t_on = “错位”；宽度超过缺口 + 1,200 秒 = “虚宽”。
4. `earlier_than: T` 按区间 [档案起点, T] 判定。

两个指标互相独立：一题可以“未命中但校准”，也可以“命中但编造精度”（原始未覆盖却猜中了）。

其他：

- 早于 t_on 且落在标签 1 区间内：另记“早于证据”，人工复核引用的读数后分“真先兆 / 猜的”。
- 缺口：起点落在记录缺口里时真值为区间 (最后一个正常读数, 第一个异常读数]；本数据集有时间戳的行之间无缺口，此规则只在 2.1 人为制造缺口时生效。
- 注入误报题：正常运行，t 按种子随机抽（≥ 1,800 秒处），系统标记一个随机传感器；正确答案 `onset: none`。
- 覆盖率：每个计数旁写“有答案 / 登记题数”。超时、传输失败、撞输出上限的题不计入任何一项，单独报。
- 成本：每题实际用掉的唯一秒数和实际计费 token；**每个正确答案的成本**（token ÷ 指标一命中数）各组各档都报。
- 取证命中（D）：取回的窗口是否覆盖 t_on；第一次取证离 t_on 多远。

## 7. 预测（登记时填 [__]）

- **P1（主）**，两个条件同时成立才算成立：① 交互作用 Σ_段 [(D对 − E对)t₂ − (D对 − E对)t₁] ≥ [__]；② t₂ 上 D 比 E 至少多对 3 题。都按指标一、K = 1,800、±120。只满足 ① 读作“D 在 t₁ 有工具开销”，不读作 D 在 t₂ 有价值。另报符号检验。
- **P2**：t₂ 上，E 从 K = 600 到 1,800 至少多对 2 题；1,800 → 3,600 不预测方向（更长的原始数据也可能干扰）。E 的窗口覆盖率随 K 单调不减是机械事实，不是预测。
- **P3**：t₂ 上 B 比 D 多对 ≥ 3 题；t₁ 上两者相差 ≤ 2 题。
- **P4**：F2 与 D 相差 ≤ 3 题；F1 另报。
- **P5**：E 和 D 在原始未覆盖 t_on 的答案里，“编造精度”多于“校准”（1.0：1,986 个事件里 UNKNOWN 为 0）。
- **P6（次要）**：注入误报题上 D 编造起始的 ≤ [__] 题。
- **P7（次要）**：D 在 t₂ 答错的题里报晚的多于报早的；其中取回窗口已覆盖 t_on 的占多数。
- **G 参照**（推算，不是预测）：δ ~ U[60, 300]，t₁ 命中率按容差 ±60 / 120 / 180 为 0% / 25% / 50%；t₂ 为 0。
- 差 3 题以内不解读。

**解读规则补充**：

- D 输了的不对称：单一模型上 D 不如 E 或 F，只能说明 Opus 5.5 的检索策略在这个任务、这个预算和 4 次取证下没有增量，不能说明主动回看没有价值；D 赢了是更强的证据。
- F → D 的“值不值”：D 只有在比 F2 多对 ≥ 3 题、且多对的题集中在 F2 答错的题上时，才算比经典算法多出能力；同时报每个正确答案的成本。

## 8. 模型、执行与花费

- **主模型：Opus 5.5**，跑全部设计。理由：D 需要可靠的多轮工具调用，用弱模型 D 输了分不清是“回看没价值”还是“不会用工具”；1.0 里它跑过 3 次，适配器和记录规则现成；P5 直接外推它在 1.0 的结果。
- **扩展模型（有条件，现在登记）**：一个不同家族的模型（Gemini Flash 或 GLM），只跑 K = 1,800 的 A / E / B / D，只在 Opus 显示出交互作用、且负责人另行同意时跑；P1–P7 不为它重述，报成扩展。
- 顺序：本文件冻结 → 生成题目（公开题入库，保留题本地 + sha256）→ 三个假智能体（总答“现在”、随机取窗、Oracle）跑完管线、计分器、预算记账 → 登记（填 [__]，写花费上限）→ 冒烟（Opus，每组 3 道公开题 K = 1,800；600 / 3,600 各 1 题；记实际计费 token）→ 正式运行（跑到一半核对实付，超估算 1.5 倍即停）→ 公开部分分析完、代码冻结后跑保留集一次 → 扩展模型（有条件）。
- 花费上限 = 冒烟实测单题成本 × 题数 × 2。估算方法和数字在设计文档“花费”一节。

## 9. 自动检查（每次运行）

1. 发给模型的每个数值的时间 ≤ t；
2. 请求里没有文件名、运行编号、钟面时间、揭示性词语；
3. 同一题同一 t 重放两次，工具返回完全一致；
4. 每次工具调用返回的最晚时间戳 ≤ t；
5. 每题每通道唯一秒数 ≤ K；E、B 的窗口长度恰为 min(K, 档案长度)；
6. 每个运行时间单调、无跨午夜；模型收到的全是相对秒；
7. 输出上限 ≥ 8k，记停止原因。
